## [09:20] Session — Ship the Entrepreneur and CPA packs; port vault-health to tolvi-format

**Tickets:** none

### What happened
- Added `packs/entrepreneur` (7 templates) and `packs/cpa` (6 templates), closing the two packs the README had advertised as planned. `install.sh` needed no change — it resolves packs by directory and lists available ones with `ls`, so both worked the moment the directories existed.
- Caught a brand-isolation problem before it reached the public repo: the vault-health work sat in eighteen unpushed commits whose diffs named a sibling product, referenced its source file, and embedded a staging path with a real vault hash. Public history had zero such references, so pushing as-is is what would have broken isolation.
- Split the skill in two. The sibling-specific version was copied to that product's own repo under `.claude/skills/vault-health/`, where its checks are meaningful and its 59 tests still pass. The copy in this repo was ported to tolvi-format and wired into `install_stack_skills()` alongside `/tolvi-bastion` and `/tolvi-guild`.
- Rewrote the eighteen commits so the sibling references never enter public history, keeping a backup bundle of the pre-rewrite state first.

### Decisions worth remembering
- **The port was a rewrite, not a rename.** Four of the nine checks could not fire on a tolvi-format vault at all — two keyed on a `summary:` field the schema has no equivalent of, one required a `people/` directory produced by the other product's entity router, and one keyed on `type: task`. Two more keyed on a `title:` frontmatter field that tolvi-format does not have, since a tolvi note's title is its first `# Heading`. Scrubbing the terms alone would have shipped a skill that silently found nothing.
- **The surviving set is five graded checks plus one structural.** `empty-tags`, `duplicate-title` (retargeted to the body heading), `status-enum` (retargeted to the tolvi vocabulary of active / in-progress / draft / superseded / deprecated), `unicode-escaping`, and a new `template-placeholder`, with `unparseable-frontmatter` reported separately and excluded from grades. `template-placeholder` replaces the dropped junk-fixture check and earns its place here, since a vault provisioned from templates fails most often by leaving them half-filled.
- **`template-placeholder` looks only at frontmatter values and heading lines, never body prose.** The first version searched raw text and immediately produced a false positive on a decision that documented the `vault/sessions/YYYY-MM-DD.md` naming convention. Prose legitimately mentions these tokens; an unfilled template shows them in frontmatter. Both false-positive cases are now regression tests.
- **`templates/` is skipped entirely by the loader.** Those files are unfilled by design and would otherwise trip every placeholder check.
- **An absent `status:` counts as `active`**, matching what the recall skills already assume, so a note omitting the key is not a defect.
- **The author email was left alone.** The sibling repo rewrote author identity to a GitHub noreply address before its first public flip, but this repo's already-public history carries the real address on nine of ten commits, so rewriting the new commits would be inconsistent and would recover nothing.
